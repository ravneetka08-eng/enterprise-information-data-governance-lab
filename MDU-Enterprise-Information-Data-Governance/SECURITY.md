# Security and responsible publishing

- Never publish passwords, app secrets, tokens, API keys, tenant IDs, email addresses of real people or student records.
- Use only fictional test users and synthetic documents; sanitise screenshots (browser URL, account details, document names and people).
- Do not apply retention deletion policies to production content; test in isolated, non-production scope.
- Do not enable broad external sharing to demonstrate risk; document it as a tabletop scenario instead.
- Do not run automation against an organisation's tenant without written permission.
- Keep audit evidence accurate and date-stamped; do not fabricate screenshots or results.
